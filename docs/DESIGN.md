# Дизайн-система «ДомКруг»

**Версия:** 1.1 · **Дата:** 08.11.2026 · **Статус:** ACTIVE
**Foundation:** обновлён в ветке `design/ui-kit-foundation`; см.
`docs/DESIGN-IMPLEMENTATION.md`.

---

## 1. Принципы

1. **Понятно человеку 65 лет.** Основной пользователь приложения — не айтишник, а житель, который звонит в УК. Крупный шрифт, явные подписи, никаких иконок без текста.
2. **Быстро человеку в стрессе.** Диспетчер работает под звонком. Один экран — одно действие. Минимум кликов до «взять заявку».
3. **Честные статусы.** Пользователь всегда понимает, что происходит с заявкой и что будет дальше.
4. **Зелёный — акцент, не фон.** Цвет означает действие и статус, а не украшение.

**Правило:** статус обозначается **цветом + текстом**, никогда только цветом. Часть пользователей не различает оттенки.

## 3. Типографика

**Шрифт:** Manrope — заголовки, Inter — интерфейс и текст. Оба подключены
локально через `@fontsource-variable/*`, без Google Fonts и внешнего запроса
в рантайме. Fallback — `Segoe UI`, system-ui, sans-serif.

| Токен | Размер / межстрочный | Применение |
|---|---|---|
| `--text-display` | 56 / 60 | Только лендинг и крупные акценты |
| `--text-3xl` | 32 / 40 | Заголовок страницы |
| `--text-2xl` | 26 / 32 | Заголовок секции |
| `--text-xl` | 21 / 28 | Заголовок карточки |
| `--text-lg` | 18 / 26 | Крупный текст |
| `--text-base` | 16 / 24 | Основной текст жителя |
| `--text-md` | 15 / 22 | Плотный текст УК |
| `--text-sm` | 13 / 18 | Подписи, метаданные |
| `--text-xs` | 12 / 16 | Служебное, не для жителя |

**Начертания:** 400 обычный, 500 средний, 600–700 кнопки/заголовки.
Курсив не используем. Для жителя основной текст — 16 px, для УК — 15 px.

## 5. Компоненты

### 5.1. Кнопки

| Тип | Стиль | Когда |
|---|---|---|
| Primary | `--brand-600`, белый текст | Главное действие на экране (одно) |
| Secondary | `--surface-soft`, тёмный текст | Альтернатива |
| Outline | прозрачная, рамка `--border-strong` | Альтернатива на светлом |
| Ghost | Прозрачная | Второстепенные |
| Accent | `--liviti-lime`, тёмный текст | Только на тёмных поверхностях |
| Danger | `--status-rejected` | Удаление, отклонение |

**Высота:** 48px (житель), 40px (УК). **Минимальная зона нажатия — 44×44px** всегда.
**Форма:** pill 999 для основных действий; компактные действия УК — 12px
(осознанное исключение для плотных таблиц).

**Состояния:** обычное, ховер, нажатое, загрузка (спиннер, кнопка блокируется), недоступное (opacity 0.5 + причина в тултипе).

**Правило:** одно главное действие на экран. Если хочется два primary — значит экран делает две вещи.

### 5.2. Поля ввода

- Высота 48px (житель) / 40px (УК).
- Лейбл **над** полем, всегда видимый (не placeholder вместо лейбла).
- Ошибка — под полем, красным, с конкретикой: «Введите номер квартиры», а не «Ошибка».
- Обязательные поля помечаются `*` в лейбле.
- Автозаполнение телефона — `inputmode="tel"`.

### 5.3. Бейдж статуса

```
┌──────────────────┐
│ ● В работе       │   фон: --status-progress с 12% прозрачности
└──────────────────┘   текст и точка: --status-progress
```

Высота 24px, радиус 12px, шрифт 13px/500. Точка слева — дополнительный признак, не единственный.

### 5.4. Карточка заявки (список)

```
┌───────────────────────────────────────────────┐
│ №42 · Сантехника              ● В работе      │
│ Течёт кран на кухне                            │
│ ул. Ленина, 1 · кв. 42                         │
│ Сидоров П. · срок: сегодня 18:00  ⚠ просрочено │
└───────────────────────────────────────────────┘
```

Приоритеты чтения: статус → тема → адрес → исполнитель/срок.
Аварийная — красная полоса слева 4px.

### 5.5. Пустые состояния

Не «нет данных», а что делать:

```
┌────────────────────────────────────┐
│  Заявок пока нет                    │
│  Когда появится первая — она будет  │
│  здесь.                             │
│  [ Создать заявку ]                 │
└────────────────────────────────────┘
```

### 5.6. Уведомление (тост)

Сверху (мобайл) / справа сверху (десктоп), 4 секунды, с кнопкой «Закрыть». Ошибки — не исчезают сами.

### 5.7. Загрузка фото

- Кнопка «Добавить фото» открывает камеру на телефоне (`capture`).
- Превью 80×80 с крестиком.
- Прогресс загрузки — полоса под превью.
- Лимит 5 фото, 10 МБ каждое — с явным сообщением.

### 5.8. Скелетоны

При загрузке списка — серые блоки той же формы, не спиннер по центру. Спиннер только для действий (отправка формы).

## 6. Экраны MVP

### 6.1. Житель (5 экранов)

| Экран | Содержимое |
|---|---|
| **Главная** | Приветствие, адрес и УК, статус привязки, кнопка «Создать заявку», активные заявки (2–3), последние новости |
| **Мои заявки** | Список с бейджами статусов, фильтр «Активные / Все» |
| **Создать заявку** | Категория (сетка крупных кнопок с иконками), срочность, описание, фото, телефон. Один экран, без визарда |
| **Заявка детально** | Статус, история (вертикальная лента), фото, комментарии, кнопка «Проблема не решена» (для закрытых) |
| **Профиль** | ФИО, телефон, привязки, уведомления, выход, политика ПДн |

**До подтверждения привязки:** главная показывает «Ожидает подтверждения» + телефон диспетчера УК. Кнопка создания заявки недоступна с пояснением.

### 6.2. Диспетчер (4 экрана)

| Экран | Содержимое |
|---|---|
| **Инбокс** | Список заявок, фильтры (статус, категория, дом, просрочка), поиск, сортировка. Плотный список, не карточки |
| **Карточка заявки** | Все данные, история, комментарии (вкл. служебные), действия: принять / назначить / отклонить |
| **Привязки на подтверждение** | Список ожидающих, кнопки подтвердить/отклонить с причиной |
| **Новая заявка по телефону** | Форма с выбором дома/квартиры, источник «звонок» |

### 6.3. Исполнитель (3 экрана)

| Экран | Содержимое |
|---|---|
| **Мои заявки** | Только назначенные, сгруппированы: «В работе», «Ожидают», «Закрытые сегодня» |
| **Заявка** | Адрес, описание, телефон жителя (только пока активна), фото проблемы, кнопки смены статуса |
| **Закрытие** | Результат (обязательно), фото результата (обязательно), подтверждение |

### 6.4. Админ УК (5 экранов)

| Экран | Содержимое |
|---|---|
| **Дома** | Список, карточка дома со счётчиками (квартир, жителей, открытых заявок) |
| **Квартиры** | Таблица, импорт CSV |
| **Сотрудники** | Список, роли, деактивация |
| **Категории и SLA** | Список категорий, сроки |
| **Новости** | Список, создание, публикация |

## 7. Доступность и возраст

Требования, а не пожелания:

1. **Контраст** текста ≥ 4.5:1, крупного ≥ 3:1.
2. **Минимальная зона нажатия** 44×44px, между кнопками ≥ 8px.
3. **Шрифт не мельче 16px** в интерфейсе жителя.
4. **Фокус видим** — обводка 3px `--focus` с offset 2px при навигации с клавиатуры.
5. **Не только цвет** — статус всегда с текстом.
6. **Масштаб 200%** без потери функциональности.
7. **Формы:** ошибка — и текстом, и связью с полем (`aria-describedby`).
8. **Язык** — русский, без англицизмов в интерфейсе жителя («заявка», не «тикет»).

## 8. Адаптив

| Диапазон | Поведение |
|---|---|
| < 640px | Мобайл: одна колонка, нижняя навигация у жителя, полноэкранные формы |
| 640–1024px | Планшет: две колонки в списках, боковая навигация |
| > 1024px | Десктоп: список + деталь в двух панелях у диспетчера |

**Диспетчер на мобайле** — поддерживается, но не оптимизируется: основное место работы — компьютер.

## 9. Иконки, бренд и различие продуктов

- **Иконки:** набор Lucide (MIT), толщина 1.5–2px, размер 20/24px.
- **Логотип:** `liviti`; временный знак — `l` в скруглённом квадрате.
  Финальный SVG ещё не утверждён, поэтому не фиксируем его как окончательный.
- **Название в интерфейсе:** `liviti`, в тексте — Liviti / «ДомКруг» как проект.

### 9.1. Житель и УК: один бренд, два режима

Не различать продукты отдельным цветом бренда. Различие — в каркасе,
плотности и подписи:

| Признак | Житель | Кабинет УК |
|---|---|---|
| Каркас | Светлая шапка, бумага | Deep Ink-сайдбар/шапка |
| Навигация | Верхнее меню + нижняя навигация | Боковое меню, группы |
| Плотность | 16 px, карточки, 48 px | 14–15 px, таблицы, 40 px |
| Геометрия | Радиусы 16–22, pill | Радиусы 8–12, компактные |
| Подпись | «Моя квартира · адрес» | «Кабинет УК · УК» |
| Акцент | Зелёный + бумага | Ink + зелёный на действиях |

Синий акцент УК убран: `apps/staff/src/theme.css` помечен DEPRECATED и не
импортируется. Шапка УК теперь Deep Ink, активный пункт — лаймовый;
в production используется sidebar 236 px, на мобильном — горизонтальная
шапка и нижняя навигация.

## 10. Что НЕ входит в MVP

- Тёмная тема.
- Кастомные иллюстрации.
- Анимации сложнее 150ms fade.
- Полный Storybook: вместо него dev-галерея `apps/ui-kit` на реальных
  компонентах. Если понадобятся controls/docs/a11y-addon в стандартном
  виде — добавим отдельно.

**Правило:** сначала работает, потом красиво. Но базовые вещи (контраст,
размер кнопок, пустые состояния) — сразу, иначе переделывать всё.
