# Живой тест параллельного вызова домофона

**Дата подготовки:** 07.11.2026
**Статус:** подготовлено, ждёт человека у панели
**Код:** `scripts/ring-indoor.py`, `scripts/intercom-parallel-check.sh`,
диалплан `[from-panel]` на сервере

---

## 1. Что проверяем

Схема из `docs/INTERCOM-HIKVISION.md` §3.8:

```
курьер нажимает кнопку
        │
        ├─ панель звонит по VoIP (приоритет 0) ─────► Asterisk ──► приложение
        │                                              │
        │                                              └─ ring-indoor.py
        │                                                        │
        └─ панель звонит монитору (callSignal indoor) ◄──────────┘
```

Главный неизвестный вопрос: **не ответит ли панель `deviceBusy`**, пока сама
звонит по VoIP. Если ответит и будет занята весь разговор — монитор зазвонит
только после него, и схему надо переворачивать.

Ответ даёт только живое нажатие кнопки: API-эмуляция звонка с панели
отсутствует, а `callSignal` — это и есть проверяемая команда.

---

## 2. Что должно быть готово

| Что | Как проверить |
|---|---|
| Туннель до панели | `curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:18081/ISAPI/System/deviceInfo` → 401 |
| Панель 6001 в Asterisk | `sudo asterisk -rx 'pjsip show contacts'` → строка `6001/` |
| Триггер в диалплане | `sudo asterisk -rx 'dialplan show from-panel'` → `ring-indoor.py` |
| Монитор подключён к панели | визуально: монитор в офисе, привязан к комнате 100 |
| Человек у панели | нажать кнопку вызова квартиры 100 |

Preflight одной командой:

```bash
bash scripts/intercom-parallel-check.sh
```

Скрипт ничего не звонит: только читает состояние.

---

## 3. Ход теста

1. На сервере открыть журнал:

   ```bash
   sudo tail -f /tmp/ring-indoor.log
   ```

2. Во втором окне — каналы Asterisk:

   ```bash
   sudo asterisk -rvvv
   # или: sudo asterisk -rx 'core show channels'
   ```

3. Человек у панели нажимает кнопку вызова квартиры **100**.

4. Одновременно смотреть:

   - появился ли входящий звонок в приложении жителя;
   - зазвонил ли монитор;
   - что пишет журнал:

     | Запись в журнале | Значение |
     |---|---|
     | `попытка 1: 200 {... OK ...}` | панель приняла `callSignal` — параллель работает |
     | `попытка N: 200` | сработало не с первой попытки, но сработало |
     | `deviceBusy` несколько раз | панель занята VoIP-вызовом — параллели нет |
     | `нет параметров сессии: 404` | сессионный логин не прошёл, смотреть `panel.env` |

5. Завершить звонок. В журнале должна появиться строка `hangup`.

6. Записать результат в `PROGRESS.md`: время, комната, ответ панели,
   зазвонил ли монитор, зазвонило ли приложение, задержка.

---

## 4. Как трактовать результат

| Результат | Вывод |
|---|---|
| `200` + монитор звонит одновременно с приложением | схема работает; зафиксировать и оставить |
| `deviceBusy` до конца разговора, монитор звонит позже | параллели нет; вернуться к варианту «30 секунд» из §16.3 или менять железо |
| `200`, но монитор не звонит | проверить привязку монитора к комнате 100 на панели |
| `404` при сессии | проверить `/etc/domkrug/panel.env` и права `root:asterisk 640` |

---

## 5. Откат

Тест ничего не меняет в конфигурации панели. Если монитор продолжает
звонить после теста:

```bash
sudo python3 /srv/domkrug/scripts/ring-indoor.py hangup
```

Если меняли приоритет вызова на панели — исходник лежит в
`/root/panel-callpriority-backup.json` на сервере (см.
`docs/INTERCOM-HIKVISION.md` §16.6).
