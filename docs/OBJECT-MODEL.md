# Объектная модель и паспорт объекта

Статус: **первый срез + собственники, 08.11.2026**. Финансы, бухгалтерия
и биллинг в этот этап не входят.

## Зачем

Кабинет УК должен расти не вокруг «квартиры», а вокруг объекта управления.
Один и тот же продукт должен уметь работать с МКД, коттеджным посёлком,
смешанным объектом и нежилым зданием. Поэтому в `buildings` появился
`object_kind`, а данные паспорта вынесены в отдельную таблицу.

## Иерархия

```
УК (tenant)
  → объект управления (buildings.object_kind)
    → помещение (apartments.kind)
      → собственник (owners)
        → право: доля, роль, период (ownerships)
      → пользователь приложения (resident_bindings) — отдельно
```

Собственник — физическое лицо, а не учётная запись. Один и тот же человек
может владеть несколькими помещениями; доступ в приложение выдаётся
отдельной привязкой.

## Типы объектов

`buildings.object_kind`:

- `apartment_building` — МКД, основной сценарий;
- `cottage_settlement` — коттеджный посёлок: дома, участки, общая
  территория, КПП, дороги;
- `mixed_use` — жилая и коммерческая части в одном объекте;
- `commercial_building` — нежилое здание.

Тип хранится в объекте, а не в отдельном приложении. Паспорт и карточка
объекта общие; отличается состав помещений и набор инфраструктуры.

## Паспорт

Таблица `building_passports`, один паспорт на объект:

- кадастровый номер;
- год ввода в эксплуатацию;
- общая, жилая, коммерческая площадь;
- площадь земельного участка;
- машиноместа;
- количество лифтов;
- класс энергоэффективности;
- дата начала управления;
- гарантия до;
- заметки.

Год постройки, этажность и число подъездов остаются в `buildings`: это
свойства самого объекта, а не паспортной карточки.

## Собственники

Таблицы `owners` и `ownerships`:

- `owners` — ФИО, телефон, e-mail, заметки; не является пользователем;
- `ownerships` — помещение, собственник, роль (`owner` /
  `representative`), доля в процентах, период права, кто создал.

Право можно изменить или убрать; запись архивируется (`deleted_at`).
Если у человека не остаётся других прав в УК, его карточка тоже
архивируется.

## Помещения

`apartments.kind` теперь поддерживает:

- `apartment` — квартира;
- `nonresidential` — нежилое;
- `house` — дом;
- `office` — офис;
- `retail` — магазин;
- `parking` — паркинг;
- `storage` — кладовая.

Тип, комнатность, площадь и статус меняются через
`PATCH /buildings/:id/apartments/:apartmentId`. В паспорте появилась
вкладка «Помещения»; масса помещений заводится CSV-импортом.

Импорт: `POST /buildings/:id/apartments/import`, до 1000 строк,
обязательные поля `number`, `kind`; `rooms` и `area` необязательны.
Дубли по номеру пропускаются, существующие данные не перезаписываются.

## Счётчики

УК может:

- добавить прибор: тип, серийный номер, единица, поверка, начальное
  показание;
- изменить прибор;
- отключить/включить.

API: `GET /buildings/:id/meters`,
`POST /buildings/:id/apartments/:apartmentId/meters`,
`PATCH/DELETE /buildings/:id/meters/:meterId`.
Чтение — `apartment.view`, запись — `apartment.manage`.

## API

- `GET /api/v1/buildings/:id/passport` — объект, паспорт, состав и
  счётчики; право `building.view`.
- `PUT /api/v1/buildings/:id/passport` — полное сохранение паспорта;
  право `building.manage`, запись в аудит.
- `GET /api/v1/buildings/:id/owners` — реестр собственников;
  право `apartment.view`.
- `POST /api/v1/buildings/:id/apartments/:apartmentId/owners` — создать
  собственника и право; `PATCH`/`DELETE` — изменить/убрать; право
  `apartment.manage`, аудит.
- `PATCH /api/v1/buildings/:id/apartments/:apartmentId` — тип,
  комнатность, площадь, статус.
- `POST /api/v1/buildings/:id/apartments/import` — CSV-импорт помещений.
- `GET/POST/PATCH/DELETE /api/v1/buildings/:id/.../meters` — счётчики.

`GET /api/v1/buildings` теперь отдаёт `objectKind`, поэтому реестр
объектов и паспорт используют один тип.

## UI

- `/objects` — реестр объектов: адрес, ЖК, тип, помещения, открытые
  заявки. Строка кликабельна.
- `/objects/:id` — паспорт: вкладки «Обзор», «Помещения»,
  «Собственники», «Счётчики».
- `/objects/:id/units` — помещения, тип/площадь/статус.
- `/objects/:id/owners` — собственники и доли.
- `/objects/:id/meters` — приборы учёта.
- `/objects/:id/import` — CSV-импорт помещений с предпросмотром.

## Что сознательно не вошло

- история изменений права и документы-основания;
- объединение дублей физлиц;
- импорт домов и собственников (пока только помещения);
- оборудование/документы как вкладки;
- финансы, тарифы, начисления, оплаты;
- создание объектов через UI.
