## 1. Туннель офис → сервер (блокирует всё, делать первым)

Нужно, чтобы сервер видел **только адреса панелей**, а не всю офисную сеть.

- WireGuard на офисном мини-ПК, постоянное соединение с `198.51.100.10`.
- Маршруты **только** на `192.168.2.108` и `192.168.2.109` (или NAT на нужные
  порты). Офисный интернет через сервер не гонять, в остальную офисную сеть не
  пускать.
- Ключи WireGuard — в менеджер паролей, не в репозиторий.

**Критерий готовности** (выполнить с сервера):

```bash
curl -s -o /dev/null -w '%{http_code}' http://192.168.2.108/ISAPI/System/deviceInfo
# ожидаем 401 — устройство ответило, нужен пароль
```

## 2. Пользователь AMI для бэкенда

Файл `/etc/asterisk/manager.d/liviti.conf`:

```ini
[liviti]
secret = <сгенерировать, 20+ символов>
read = call,system
write = call
permit = 127.0.0.1/32
```

```bash
sudo asterisk -rx 'manager reload'
sudo asterisk -rx 'manager show user liviti'
```

**Критерий готовности:** логин и пароль у меня (или скажи «создай сам» —
файл доступен через sudo). После этого события звонка пойдут в приложение.

## 5. WSS для браузера (звук в приложении)

Чтобы житель слышал и говорил с сайта:

- `transport-wss` в `pjsip.conf` на порту `8089`;
- сертификат от Caddy (домен `liviti.ru` уже с HTTPS);
- обязательно `external_media_address=198.51.100.10`, иначе в SDP уйдёт
  приватный адрес и звука не будет.

**Критерий готовности:** `ss -ltn | grep 8089` показывает порт. Проксирование
`/ws` через Caddy сделаю я.
