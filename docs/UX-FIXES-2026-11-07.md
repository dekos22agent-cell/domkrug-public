# UX-правки по замечаниям владельца (07.11.2026)

Пакет из 11 замечаний: обращение по ФИО, регистрация, привязка, доступ,
экстренное, шапка кабинета, главная после входа, карточка квартиры,
переключатель квартир и отвязка.

---

## 1. Обращение по ФИО

**Было:** «Иван Петрович Сидоров» → «Здравствуйте, Петрович Сидоров».

**Стало:** `greetingName` понимает оба порядка — фамилия первой и имя
первым. Ориентир — отчество: у него устойчивые окончания (`-ович`, `-евна`,
`-ична` и т. п.). Для двух слов без отчества фамилия узнаётся по окончанию.

| Ввод | Обращение |
|---|---|
| Иванов Иван Иванович | Иван Иванович |
| Иван Петрович Сидоров | Иван Петрович |
| Петров Иван | Иван |
| Иван Петров | Иван |

Файл: `packages/shared/src/format.ts`, тесты — `format.test.ts`.

## 2. Несовпадение паролей при регистрации

**Было:** ошибка появлялась только после нажатия «Зарегистрироваться».

**Стало:** как только в поле «Пароль ещё раз» появляется отличие, под ним
сразу видно «Пароли пока не совпадают». Нажатие кнопки больше не нужно.

Файл: `apps/resident/src/pages/RegisterPage.tsx`.

## 3. «Адрес не найден» при привязке

**Было:** мелкая серая строка внизу результатов.

**Стало:** заметный блок с заголовком «Адрес не найден», объяснением
(проверить улицу/дом, новый дом мог ещё не попасть в систему) и кнопкой
«Попробовать другой адрес».

Файл: `apps/resident/src/pages/BindingPage.tsx`.

## 4. Доступ чекбоксами вместо пресетов

**Было:** выпадающий список «Член семьи / Ребёнок / Арендатор / Рабочий /
Гость»; отдельно выбрать двери было нельзя.

**Стало:** чекбоксы по типам точек — подъезд, калитка, шлагбаум, ворота,
парковка. Для приглашения по телефону дополнительно видео, показания,
заявки, начисления. Для кода — только двери: без аккаунта остальное
недоступно.

**Модель прав.** Добавлены права `access.entrance_door`, `access.wicket`,
`access.barrier`, `access.gate`, `access.parking`. Старое `access.open`
осталось и означает «все точки» — существующие приглашения работают без
миграции данных. Проверка открытия смотрит на тип конкретной точки.

| Файл | Что |
|---|---|
| `backend/migrations/022_access_kind_scopes.sql` | в `apartment_rights` добавлена колонка `scopes` |
| `backend/src/modules/access/service.ts` | фильтр точек и проверка типа при открытии |
| `backend/src/modules/members/*` | API принимает `scopes` |
| `apps/resident/src/pages/MembersPage.tsx` | чекбоксы вместо селекта |

Старые пресеты (`child`, `worker`, …) остаются в API для совместимости;
интерфейс их больше не показывает.

## 5. Hover на плитках экстренных служб

**Было:** при наведении текст подчёркивался (глобальное правило для ссылок).

**Стало:** подчёркивания нет; плитка приподнимается на 2 px, появляется
тень, у светлых плиток меняется фон. Нажатие остаётся очевидным.

Файл: `apps/resident/src/pages/utilities.module.css`.

## 6. Аварийная служба и обычная заявка

Добавлено пояснение прямо на экране «Экстренно»:

## 7. Шапка кабинета УК

**Было:** имя мелкое, рядом текстовая кнопка «Выйти».

Файлы: `apps/staff/src/StaffLayout.tsx`, `StaffLayout.module.css`.

## 8. Имя жителя на главной после входа

**Было:** на liviti.ru всегда «Войти жителю», даже если человек вошёл в
приложении или кабинете.

**Стало:** главная спрашивает сессию и показывает имя и «Выйти»; имя ведёт
в кабинет (сотруднику — в УК, жителю — в приложение).

| Что | Как |
|---|---|
| cookie | `COOKIE_DOMAIN=.liviti.ru` в production — cookie видна на всех поддоменах |
| проверка | `GET /api/v1/auth/session` читает httpOnly-cookie и не ротирует токен |
| главная | `apps/landing/src/useSession.ts`, имя и «Выйти» в шапке |

`/auth/session` намеренно **не** обновляет refresh-токен: иначе каждый заход
на главную выглядел бы как повторное использование токена и мог закрыть
все сессии.

## 9. Карточка квартиры

**Было:** на экране «Квартира» только адрес и статус.

**Стало:** по клику на привязку открывается окно: площадь, комнаты, этаж,
подъезд, тип помещения, год/этажность/число подъездов дома, УК, роль и
статус. Данные приходят в `/auth/me` вместе с привязкой.

Файлы: `apps/resident/src/pages/BindingPage.tsx`,
`backend/src/modules/auth/service.ts`, `packages/shared/src/types.ts`.

## 10. Переключатель квартир

**Было:** в узком селекте все варианты начинались с «г. Барнаул, …», и
выбранную квартиру не было видно.

**Стало:** сначала номер квартиры, потом адрес без города:

```
кв. 1 · ул. Ленина, 1 · моя
```

Полный адрес — в подсказке `title`. Ширина селекта увеличена.

Файлы: `packages/ui/src/Layout.tsx`, `Layout.module.css`,
`packages/shared/src/format.ts` (`shortAddress`).

---

## 11. Отвязка квартиры

**Было:** подтверждённую привязку нельзя было отозвать — только через УК.

**Стало:** на карточке и в окне квартиры есть «Отвязать квартиру» с
подтверждением. Сервер удаляет привязку, пишет в аудит
`resident.binding_revoke`, доступ к квартире закрывается сразу.

Файлы: `apps/resident/src/pages/BindingPage.tsx`,
`backend/src/modules/bindings/service.ts`, `routes.ts`.

## Дополнение 08.11.2026

### Шапка жителя — как в кабинете УК

Имя в приложении жителя теперь крупнее (15 px, вес 500) и ведёт в
профиль; «Выйти» — иконкой с `aria-label`. Раньше в жителе оставалась
мелкая подпись и текстовая кнопка.

Файлы: `packages/ui/src/Layout.tsx`, `Layout.module.css`.

### Главная: только кнопка своей роли

Вошедшему показываем только его кнопку: жителю — приложение, сотруднику —
кабинет. Гость видит обе. Спрятаны и кнопка в шапке, и основная кнопка
в герое.

Файл: `apps/landing/src/App.tsx`.

### Перезагрузка и две refresh-cookie

После перехода cookie на `.liviti.ru` в браузере могли остаться **две**
cookie с именем `refresh_token`: старая host-only и новая доменная.
Браузер отправляет обе, сервер читал устаревшую — и после перезагрузки
сессия пропадала.

Теперь при входе и обновлении токена host-only удаляется перед установкой
доменной; при выходе чистятся оба варианта.

Файл: `backend/src/modules/auth/routes.ts`.

Проверка в чистом профиле: вход → reload → `/` и `refresh 200`; в
`Network.getAllCookies` одна cookie с `domain=.liviti.ru`.

Проверка на проде: шапка жителя — имя 15 px и иконка выхода; reload
остаётся на `/`; после ручной подстановки второй (host-only) cookie
повторный вход оставляет только доменную; на главной у жителя нет
«Кабинет УК» в шапке и «Кабинет для УК» в герое, кнопка приложения
жителя на месте.
