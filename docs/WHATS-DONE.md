# liviti — что уже реализовано

Сводка по состоянию на 05.11.2026. Пилот: **https://liviti.ru**
(прежний `1brn.ru` отвечает постоянным перенаправлением).

Продукт: цифровая среда для современной жизни. Многоквартирные дома:
управляющая компания и жители в одном приложении.

---

## 1. Основа

| Что | Как |
|---|---|
| Мультитенантность | `tenant_id` на всех бизнес-таблицах; одна база, данные УК не пересекаются |
| Стек | Node.js 22 + TypeScript + Fastify 5, PostgreSQL 16, React 19 + Vite, PWA |
| База | 17 миграций (001–017), накатываются по порядку, идемпотентно |
| Развёртывание | Docker (PostgreSQL) + systemd (API) + Caddy (HTTPS), Timeweb Cloud |
| Резервные копии | pg_dump по cron в 03:30 |

## 2. Доступ и роли

- **Вход** по телефону или e-mail и паролю.
- **Access JWT** 15 минут в памяти + **refresh-cookie** 30 дней (opaque, sha256 в `sessions`),
  ротация при каждом обновлении; повторное использование украденного токена
  отзывает все сессии пользователя.
- **51 право и 6 ролей**: администратор УК, диспетчер, исполнитель, житель,
  бухгалтер, руководитель. Право отвечает на «что можно», привязка к квартире —
  на «к каким строкам».
- **Аудит**: все значимые действия пишутся в `audit_log` (кто, что, когда, IP).

## 3. Заявки — основной сценарий

- Житель создаёт заявку: категория, описание, адрес, телефон, приоритет.
- **Категории** (12): сантехника, электрика, отопление, лифт, домофония,
  канализация, уборка, благоустройство, безопасность и другие; часть —
  аварийные.
- **Номер заявки** сквозной внутри УК, выдаётся атомарно (`ticket_numbers`),
  без гонки «MAX+1».
- **Статусы** с историей: новая → в работе → выполнена / отклонена.
- **Исполнитель закрывает сразу** с обязательным комментарием. «Проблема не
  решена» → создаётся новая заявка со ссылкой `parent_ticket_id`, а не
  переоткрывается старая.
- **Матрица кнопок**: житель — создать, комментировать, удалить; диспетчер —
  назначить, переназначить, отклонить; при назначении себе — взять и закрыть;
  исполнитель — взять и закрыть; администратор — всё.
- Инбокс УК, «мои задания» исполнителя, комментарии под описанием, история
  обновляется после каждого действия.

## 4. Квартиры и привязки

- Житель ищет дом по адресу и указывает квартиру; УК подтверждает.
- У одного человека может быть **несколько квартир** в разных УК —
  переключатель квартир в шапке.
- Подтверждённая привязка = собственник: у него все права по квартире.

## 5. Члены квартиры и права

- **Семья, дети, арендаторы, рабочие, гости** — члены квартиры с набором прав.
- Права: `access.open`, `video.view`, `meters.submit`, `tickets.create`,
  `finance.view`, `members.manage` — **флаги, а не роли**.
- Пресеты: член семьи (двери + видео + показания + заявки), ребёнок (только
  двери), арендатор (как семья, со сроком), рабочий и гость (только двери,
  срок обязателен).
- **Инвайт по телефону** для тех, кому нужен аккаунт: человек регистрируется
  этим номером — доступ включается сам (телефон нормализуется, форматирование
  не мешает).
- **Доступ по коду** для тех, кому аккаунт не нужен: 8 символов, bcrypt-хеш,
  срок, отзыв в один клик. Ни регистрации, ни персональных данных, ни согласий.
- Права собраны в представление `apartment_rights` — модули проверяют
  `can_open`, `can_video`, `can_meters`, `can_tickets`, а не джойнят привязки
  по-своему.

## 6. Доступ на территорию (СКУД)

- Точки доступа: подъезд, калитка, шлагбаум.
- Открытие с телефона, **быстрые кнопки на главной**.
- Права выдаются **квартире**, а не человеку: отозвали квартиру — закрылись
  двери у всех её жильцов.
- Провайдер оборудования абстрагирован: `MockAccessProvider` для демо,
  реальный провайдер подключается без изменения сценариев.
- **Лимит 5 открытий в минуту** на пользователя, журнал `access_events`.
- Чужие точки возвращают 404 — как несуществующие, без утечки информации.

## 7. Видеонаблюдение и домофон

- Камеры двора и подъезда с правами по квартире.
- Браузер не умеет RTSP, поэтому типы потоков: `demo | hls | webrtc | sip`;
  в демо возвращается честное `demo: true`.
- **Токен доступа к камере живёт 5 минут**.
- **Звонок с вызывной панели**: всплывающее окно с картинкой панели, кнопки
  «Открыть» и «Отклонить», опрос активного вызова каждые 5 секунд.

## 8. Показания счётчиков

- Приборы по квартире: холодная и горячая вода, электричество.
- **Три правила на сервере**: один прибор — одно показание за период;
  показание не может быть меньше предыдущего; только текущий месяц.
- Повторная передача исправляет ошибку ввода за текущий период.
- История показаний и прошлый период для сверки.

## 9. Лифты

- Статус лифта: работает / на обслуживании / неисправен.
- Вызов лифта из приложения (для гостя или курьера).
- **Сообщение о неисправности создаёт настоящую заявку** в категории
  «Лифтовое оборудование» с высоким приоритетом; связь хранится
  в `lift_events.ticket_id`.
- Статус лифта меняет УК, а не житель: иначе один человек объявит лифт
  неисправным для всего дома.

## 10. Экстренные сообщения и вызовы

- Сообщения УК: по всему дому или по конкретному адресу, с уровнем важности
  (`info`, `warning`, `critical`) и сроком действия.
- **Аварийная служба УК** — вызов уходит по-настоящему, с адресом и квартирой,
  отмена возможна пока не принят, кулдаун 5 минут.
- **Экстренные службы — только звонок.** Кнопки 112, 101, 102, 103, 104
  открывают набор номера (`tel:`). Приложение не изображает «вызов отправлен
  в скорую»: через сторонние приложения они вызов не принимают, а человек
  отложит телефон и будет ждать.
- **Полезные телефоны**: УК, участковый, провайдеры, поликлиника — по УК или
  по дому, номера кликабельные.

## 11. Начисления и оплата

- Раздел «Оплата» с начислениями, расшифровкой «за что» и способами оплаты
  (пока **демонстрационные** — биллинг не подключён).
- Переход в региональную **Систему «Город»** для реальной оплаты ЖКУ.
- **Оплата только для своей квартиры**: в квартиру по доступу раздел не
  открывается, деньги — дело собственника.

## 12. Гостевой режим

- Отдельный экран `https://liviti.ru/guest` — ввод кода, затем адрес, срок
  и крупные кнопки открытия.
- Ни профиля, ни заявок, ни счётчиков, ни привязки квартиры.
- Свой тип токена `guest`: `/auth/me` и `/resident/*` отвечают 401.
- **Метка владельца гостю не показывается** (владелец может подписать доступ
  как угодно).

## 13. Интерфейс жителя

- **Главная-витрина**: приветствие, адрес, плашка «квартира не ваша» с именем
  того, кто дал доступ, быстрые кнопки открытия, начисления, плитки сервисов.
- **Плитки строятся по правам**: ребёнок видит только двери, семья — ещё
  камеры, счётчики и заявки.
- **Меню из четырёх пунктов** (Главная, Заявки, Доступ, Квартира) + профиль:
  остальное — плитками, потому что пункт, до которого надо докручивать,
  на телефоне не находят.
- **Переключатель квартир** подписывает «— моя» и «— по доступу».
- Мобильная вёрстка: кнопки и телефоны не обрезаются на 360px.

## 14. Профиль

- ФИО, телефон, e-mail, дата рождения, СНИЛС.
- **СНИЛС** с проверкой контрольной суммы и защитой от служебного диапазона.
- Смена пароля, выход, дозаполнение профиля.
- Начисления и «Семья и доступ» из профиля убраны: им место в оплате и на
  главной.

## 15. Качество

- **66 API-тестов** + юнит-тесты: авторизация, привязки, заявки, доступ,
  видео, счётчики/лифты/экстренное, члены квартиры, доступ по коду.
- `npm run typecheck`, линтер фронтенда без предупреждений.
- `scripts/check-encoding.mjs` — защита от битой кодировки в репозитории.

## 16. Что осознанно не сделано

| Не сделано | Почему |
|---|---|
| ЕСИА | 3–6 месяцев, СМЭВ, КЭП; отложено |
| Импорт недвижимости из ЕСИА/ФНС | источник истины — УК |
| Реальный медиасервер (go2rtc/MediaMTX) | нужен вещательный сервер, демо честно помечено |
| WebSocket/SSE | сейчас опрос, для пилота достаточно |
| SIP-аудио в домофоне | нужен SIP-шлюз |
| Эквайринг ЮKassa + СБП | отдельный этап, нужен договор |
| RLS на уровне PostgreSQL | отложено до мультитенантной нагрузки |
| Нативные виджеты (Capacitor) | после стабилизации веба |
| Домен liviti.ru | покупается перед публичным запуском |
| Совладельцы квартиры | открытый вопрос: как выдавать права второму собственнику |

## Идеи, которые заложены в архитектуру

1. **Право — это флаг, а не роль.** Роль отвечает «кто ты», флаг — «что можно».
   Иначе «жена, но без финансов» превращается в новую роль.
2. **Инвайт по номеру телефона, а не по ссылке.** Номер уже есть, код вводить
   не надо — человек просто входит.
3. **Код вместо аккаунта там, где данные не нужны.** Строителю не нужен профиль,
   ребёнку нельзя дать согласие на обработку ПДн.
4. **Один экран — один вопрос.** У гостя нет меню: только адрес, срок и двери.
5. **Ошибка в правах должна быть видна сразу.** Плитки строятся по правам,
   а не прячутся CSS-ом.
6. **Не изображать то, чего нет.** Экстренные службы — звонок, а не «вызов
   отправлен». Демо-данные подписаны как демонстрационные.

## 17. Домофон с реальной панели (добавлено 06.11.2026)

До 06.11 звонок в приложении был демонстрационным: кнопка «Смоделировать звонок».
Теперь звонок приходит с настоящей вызывной панели Hikvision.

**Цепочка:**

```
панель (кнопка вызова)
   | SIP
   v
Asterisk на сервере
   | AMI (127.0.0.1:5038)
   v
backend: событие Newchannel в контексте from-panel
   | запись в intercom_calls + уведомление
   v
окно «Звонок в домофон» у жителя
   |
   +-- видео с панели через go2rtc (RTSP -> WebRTC)
   +-- звук через WebRTC-клиент (WSS 8089), микрофон — только по кнопке
   +-- «Открыть» -> открытие двери по ISAPI
```

**Почему AMI, а не вебхук от панели.** Событие нажатия кнопки у Hikvision
по HTTP не отдаётся: `alertStream` содержит только события доступа,
`callStatus` остаётся `idle`, `httpHosts` панель сохраняет, но не использует.
Единственный надёжный источник — Asterisk, который видит вызов.

**Ключевые решения:**

- **Комната, а не квартира.** Панель набирает номер комнаты
  (`apartments.intercom_room`). Нет комнаты — нет звонка: фантомное «звонят
  в никуда» хуже отсутствия записи.
- **Один звонок на событие.** Реагируем только на `Newchannel` в контексте
  `from-panel`: иначе `Newstate` и `Dial` дают три записи в журнале.
- **Завершение по `Uniqueid`**, иначе при двух вызовах закрывался бы «последний».
- **Сторож звонков** закрывает зависшие вызовы и уведомляет о пропущенных.
- **Микрофон не включается сам**: браузер не должен захватывать микрофон без
  действия человека.

**Ограничения железа (проверено на стенде):**

| Ограничение | Следствие |
|---|---|
| Панель держит только одну учётку `admin` | для интеграции используется она же, права ограничены сетью |
| Приоритет вызова: 60 с на монитор, потом VoIP | окно в приложении появлялось через минуту; лечится только в веб-интерфейсе панели |
| Монитор `F-VI-3442IPWE1` не умеет сторонний SIP | параллельного звонка нет; компромисс — 30 секунд на монитор, затем VoIP |

**Что нужно на объекте, чтобы было «как надо»:** монитор с поддержкой SIP
(BAS-IP, Akuvox) либо приоритет вызова, выставленный на VoIP сразу.

## 18. Номера на вызывной панели (06.11.2026)

Панель при звонке набирает короткий номер — в её настройках это «комната».
Пока номер не задан, звонок в квартиру не приходит: сервер не может понять,
кому звонили.

| Что | Где |
|---|---|
| Поле номера у квартиры | `apartments.intercom_room`, уникально в пределах дома |
| Экран УК | «Квартиры и панель»: дом, поиск, поле номера, сохранение |
| Автозаполнение | подставляет номер квартиры во все пустые строки |
| Защита | два одинаковых номера в доме запрещены (409 ROOM_TAKEN) |

Автозаполнение не трогает уже заданные номера: монтажник мог настроить панель
иначе, и его настройка важнее нашей догадки. Нечисловые номера («12А») панель
набрать не может — они остаются на ручную правку и считаются в `skipped`.

## 19. История звонков (06.11.2026)

До этого звонки только писались в базу: житель не видел, что звонили,
пока его не было.

- `GET /resident/video/intercom/history` — последние звонки по квартирам,
  где у человека есть право открывать дверь;
- на экране «Доступ» — блок «Звонки в домофон»: точка, квартира, статус
  словами (открыли, пропущен, отклонили), время;
- длительность считается только по закрытым звонкам: у пропущенного без
  `ended_at` она иначе росла бы бесконечно.

## 20. Фотографии в заявках (06.11.2026)

Житель прикладывает снимок проблемы — по нему диспетчер решает, кого и с каким
инструментом отправлять.

| Что | Как |
|---|---|
| Где хранятся | диск сервера, `/srv/domkrug/uploads` (S3 не поднялся на этом железе) |
| Доступ | только через API с токеном, публичных ссылок нет |
| Тип файла | по первым байтам: JPEG, PNG, WebP, PDF; `photo.png` с текстом отклоняется |
| Размер | до 10 МБ, один файл за запрос |
| Экран | до 5 фото в форме заявки, миниатюры и просмотр на весь экран в карточке |

Картинка в карточке грузится blob-ом: `<img>` не умеет передавать заголовок
`Authorization`, а публичные ссылки на файлы мы не выдаём принципиально.

**Проверено на проде:** заявка №22, файл загружен (70 байт), список и
скачивание отдают `image/png`.

## 21. Профиль сотрудника УК (07.11.2026)

Сотрудник УК наконец видит себя целиком: кто он в организации, какие права
ему выдали и где сменить пароль.

| Что | Как |
|---|---|
| Данные | ФИО, телефон, e-mail; ФИО и почту можно поправить |
| Организация | УК, должность, роли — назначает администратор |
| Права | список выданных прав по группам, человеческими словами |
| Безопасность | смена пароля (после неё — вход заново) |
| Второй фактор | место готово, сам TOTP — следующий этап |

Профиль доступен из меню «Профиль» и по клику на имя в шапке. Новых
эндпоинтов не понадобилось: `/auth/me` уже отдаёт организацию, должность,
роли и права. Названия прав и ролей вынесены в общие пакеты — оба приложения
называют одно и то же одинаково.

## 22. Второй фактор для сотрудников УК (07.11.2026)

Диспетчеры и администраторы видят данные сотен квартир — теперь вход можно
защитить одноразовым кодом (TOTP), как в банковских приложениях.

| Что | Как |
|---|---|
| Включение | Профиль → Безопасность → «Подключить»: ключ для приложения и проверка кодом |
| Вход | После пароля появляется поле «Код из приложения» |
| Резервные коды | 10 штук, показываются один раз, каждый срабатывает один раз |
| Отключение | Пароль + действующий код |
| Кому нужен | диспетчер, администратор УК, администратор платформы — профиль напоминает |

Алгоритм — стандартный TOTP (RFC 6238), без внешних библиотек: подходит
любое приложение-аутентификатор. Подробности и ограничения —
`docs/2FA-TOTP.md`.

## 23. Свой поддомен у каждой УК (07.11.2026)

Управляющая компания получает адрес вида `dom-service.liviti.ru` — это её
кабинет, а не общий `uk.liviti.ru`.

| Что | Как |
|---|---|
| DNS | запись `*` уже указывает на сервер |
| Сертификат | Caddy выпускает отдельный на каждый поддомен по первому запросу |
| Проверка | перед выпуском Caddy спрашивает бэкенд, существует ли такая УК |
| Форма входа | показывает название организации с поддомена |
| Несуществующий поддомен | сертификат не выдаётся |

Без проверки любой мог бы получить валидный сертификат на произвольный
поддомен нашего домена. Подробности — `docs/WILDCARD-SUBDOMAINS.md`.
